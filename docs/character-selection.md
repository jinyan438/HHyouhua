# 全屏选将

扩展的“全屏选将”开关同时控制本地标准身份、明忠、斗地主及对决欢乐模式，默认开启，重启生效。保存键仍为 `identity_fullscreen`，沿用原设置。

斗地主直接使用身份局的选将对话框、开局武将外观组件、牌面实际宽高、技能面板和确认交互。候选武将在中央排列；左上角显示三人座位，地主红色、农民绿色；底部显示当前的地主/农民身份。单击武将查看技能，再点同一张牌确认，双将按模式要求选满后提交。

身份局在候选区右下角提供“点将”牌位，斗地主在候选武将后提供同样入口。点击打开武将包列表，支持搜索名字、内部编号或技能名；列表分批加载。在列表中第一次点击武将，牌面显示“确认选择”并在旁边显示该武将技能；第二次点击直接确认。点列表内或弹窗外的空白区域会取消待确认状态并收起技能；再次点击武将重新预览。技能面板保留文字阅读和滚动操作。确认后将真实候选按钮放入点将牌位；已有候选复用原牌，不重复添加。双将已确认的第一名保留，可继续点第二名，点将列表不再显示已确认的同源武将。点将不修改武将包或个人禁将设置，排除场上其他角色已使用的同源武将及已展示的队友专属候选。

开局武将牌和点将列表共用手势处理。长按结束只拦截本次松手产生的点击，后续点击可立即预览或确认；触摸产生的合成鼠标点击不重复计数，滑动和触摸取消不误选。长按同名武将并切换版本后，立即显示该版本技能和确认提示，同时刷新原生候选缓存、保留另一名已确认武将。确认不依赖原生界面残留的拖动标记。

换将按钮及同名版本提示的大小、边角偏移和贴图均以武将牌宽度为基准，随窗口与游戏缩放同步调整，保持相对牌面的比例。

勾玉按实时宽度设置确定左侧局部坐标，与牌面一起缩放；窗口拉伸和修改武将宽度后都会自动补偿位置，拉伸后再换将也使用相同锚点。预览中的血条关闭位置过渡动画。该外观组件同时用于武将列表和详情。

选将中的血条容器单独保留原主题的 `content-box` 计算，避免全屏界面的通用 `border-box` 规则压缩带边框的容器、把勾玉向画像中挤偏。

候选武将来自原生 `chooseCharacter` / `chooseButton`，不重新抽取或初始化角色，沿用原生叫地主、身份分配及后续规则；没有队友推荐时沿用原生 AI 选将。原生候选多于一行时可以滚动查看。没有胜率数据时不添加“最高胜率”标签。

| 斗地主玩法 | 保留的原生规则 |
| --- | --- |
| 标准 | 按地主/农民的候选数设置显示，保留双将；随机换将读取模式提供的合法候选池，同名版本仍校验禁将。 |
| 开黑 | 自己和队友的候选区分别保留，只能选择原生允许的自己的候选。 |
| 欢乐 | 保留叫地主及各玩家的固定候选分配。 |
| 兵临城下 | 保留叫地主、城池技能及队友候选区，只能选择分配给自己的候选。 |
| 智斗（本地 `online` 子模式） | 保留叫地主、20 张底牌及地主双将、农民单将要求，底牌不能作为武将选择。 |

固定候选玩法不显示随机换将或同名版本入口；使用“点将”可额外选择武将，仍保留原生单/双将要求和队友专属候选限制。联机房间、乱斗、原生自选全武将弹窗和叫地主控制弹窗继续使用原界面。

关闭或删除选将对话框时，解除监听、取消计时并恢复原生控制栏。身份局继续使用原身份牌展示动画；斗地主直接显示已分配的身份，不播放主公/反贼身份牌。

## 对决欢乐模式

仅对决欢乐模式（2v2）启用这套界面；对抗、统率、自由、剑阁、四国、官渡等其他对决玩法沿用原生界面与选将逻辑。

欢乐模式复用 OL 客户端 `SelectGeneralHappyNewWindow` 的布局：上方两张大牌，下方六列方形候选，左上角显示已经分配的敌我座位。单击候选预览武将和技能，再次点击候选或当前大牌确认。队友代选与替补按原生顺序执行；已选列表用于查看当前队伍。候选超过两行时在原候选区域滚动。

候选外框使用原版 `userinfo_hero_bg`，按原生 108×108 外框、内缩 5 像素的 98×98 画像比例排列。队友绿签直接显示原始贴图中的“友”，不叠加文字。

欢乐模式中，存在尚未选将且有原生候选池的队友时，大牌右侧显示“为他推荐”。入口使用原版 `QZt` 的 `pw_select_general_item_bg_new` 贴图；推荐头像缩进左侧小框内部，完整保留边框和阴影。点击入口，再点候选即可推荐，随后回到自己的选将；自己的预选和已选保持不变。右侧大牌和入口头像显示本次推荐，点击右侧大牌可查看技能。AI 队友在原生初始化时采用推荐武将，保留替补等原生规则；真人队友只显示推荐，不强制更换其选择。开启队友代选时沿用直接代选。

推荐后再次点击“为他推荐”可取消推荐，再点一次可重新进入推荐选择。下方已推荐的方形武将显示“推荐选择”，与“确认选择”共用样式；取消时同步清除标记、队友推荐预览和入口头像，保留自己的预选与已选。

推荐给 AI 的武将暂时保留，其他 AI 不会随机选走同源武将。取消推荐时归还预留武将。更换候选后推荐不在当前候选中、队友座位变化，或自己确认了同源武将时，推荐会失效。选将结束后释放预留和临时初始化接口。

欢乐模式默认提供12名候选，点击“更换”也提供12名；扩展从原生合法候选池补足，不改变禁将、同源武将限制或原生候选池。合法池不足12名时显示实际可用数量。保留队友代选与替补，四选顺序为自己、自己替补、队友、队友替补。

“更换”和“自由选将”沿用游戏原有控制及设置。欢乐模式不额外加入点将、同名版本或单张重新抽取入口；自由选将的全武将列表不受12名限制。队友预览只使用已经公开或原生代选中的信息。全部适配均由扩展运行时加载，不修改客户端文件。

底部使用身份选将同款进度条，选将期间保持充满，不额外限制选将时间。全部武将确认后，保留选将画面，进度条在2秒内从满流逝至空；原生座位初始化、背景和画像加载解码完成后才切入对局。超过2秒仍未就绪时继续保留画面，不强制揭开；等待期间拦住正式开局，退出或重开时解除等待。

图片和选将动画来自 `E:/AI/sanguosha`：解码客户端 `sanguosha2/work/main.js` 中的 `HIs` 类提供布局、预选与确认逻辑；边框、座位和面板纹理来自解包图集。`OL_PaiJu_Xuanjiang` 动画使用 APK 缓存中的原始 Spine 4.0.56 骨骼、图集和贴图，通过隔离的 Spine 4 运行库播放，不占用动态皮肤运行库。窗口关闭时释放动画、监听及图形资源。来源路径及 SHA-256 记录在 `assets/versus-selection/sources.json`。
