# 原版武将发光框

使用本机 `E:\AI\sanguosha` 中 Unity 客户端的四套 `Assets/Res/Effect/FxEffect/NoUIParticle/FX_paiju_zuowei0{1,2,3,4}.prefab`，对应绿、黄橙、红、蓝。资源位于 `assets/player-glow/`，`sources.json` 记录原 bundle、贴图校验值、材质颜色、层级尺寸与坐标；`original/` 保留 13 张原始贴图。

原版是多层 UI 材质效果，不是单张彩色 PNG。`tools/bake-player-glow.py` 使用 Pillow 和 NumPy 将原贴图、透明遮罩、HDR 颜色、层级位置和 UV 滚动预烘焙为四张 2560×256 的十帧精灵图，并去除原版被画像覆盖的中央填色。转换保留原始素材形状与配色，采用二维烘焙适配；不运行 Unity 的完整极坐标和扰动着色器。

六种主题统一使用青蓝可选框、橘色选中框和红色结算目标框，本地玩家与其他玩家使用相同规则。选中框对原黄橙素材作暖色校正，避免外侧光晕与红色结算框过于接近。回合框保留主题原色。动画仍为 0.9 秒循环，继续复用上述原版资源。

`targetHighlight.js` 按本机原客户端 `main.js` 的 `InActiveState2`、`ServerProxy_PubGsCUseCard/UseSpell` 和 `gns.SetSeatStatus` 规则适配：只对当前回合主动行动者明确指定的其他有效角色显示红框，不把所有受影响角色都视为指定目标。自身、无目标、装备及自动全体目标不显示红框；回合外行动、响应和被询问的触发技能也不建立新的红框。手选多名角色即使覆盖全场仍属于明确指定，不能按人数排除。技能内部确认的明确选人结果归入所属主动技能，其他角色的响应选人不会并入。

原客户端以 `DestSeatIDs` 标识明确指定对象，AOE 自动扩展只用于另一条指向线逻辑。无名杀用最终选人范围区分：上限为负数是自动全选，正数或 Infinity 是明确选取。动态范围在原生自动确认之前记录，避免选牌被清空后将自动全体目标误读为默认单目标。红框保留到事件的子结算、结束触发和后续事件全部完成，异常及对局结束时清除。嵌套事件分别持有目标，内层结束不会清掉外层的红框；结算中再次选人时，青蓝可选框和橘色选中框优先显示。

结算红框改用原版 Laya `FX_paiju_zuowei02` 的另一套红色图案：直接复制 `02__zuowei02_00.png` 为 `red-steady.png`，不修改像素，不播放循环、闪烁或过渡。该素材独立按 x=83/172、y=163 的可见边缘适配实时牌宽。来源、SHA-256 和触发代码位置记录在 `assets/player-glow/target-source.json`。

`source-player-glow.css` 在主题样式之后加载，统一动画帧和画布尺寸。四种光框的可见左边、右边统一为 80、175，底边为 204；按实际金龙边框的可见跨度换算整张图片宽度与左留边。在原光框基础上，左侧及顶部向外扩大 2px，右侧向外扩大 3px；底部落在牌面下方 1px。80–200px 牌宽下，左边固定、右边随牌宽增加。选将和武将详情继续隐藏对局状态光效。

发光框的两层伪元素统一放在武将牌内部的底层，静态画像、动态画像和武将外框均覆盖在上方。光框使用普通透明混合，按实时牌宽、牌高挖去牌面区域，避免从透明画像、暗将及边框内侧透光；外侧光晕保持显示。调整高度时，普通光框及红色结算框同步改变高度与顶部偏移，底边保持在牌面下方 1px。

校验包括原贴图及输出 SHA-256、各色十帧有效且有变化、主题资源映射、80/136/160/200px 下光框与外框的左右位置，以及实际浏览器渲染检查。
