# 玩家操作超时

在“部件管理”中开启进度条后，本地手动操作的每个选择节点独立计时，默认 15 秒，可用“操作时限”调整。四种进度条样式使用同一个实际截止时间，不再按像素数量或旧速度设置决定时长；主条和副条同时反映剩余时间。重新勾选卡牌、切换进度条样式不会重新获得完整时间。进入新的选择或后续子步骤时重新计时，游戏暂停期间停止消耗。

单次超时优先放弃当前操作：出牌空闲点结束出牌，闪、桃、无懈及可选技能询问选择取消；控制项优先选取消，否则使用该事件声明的默认项。强制弃牌、拼点选牌等不能放弃的操作继续执行原生默认选择。自带异步选择窗口的技能通过原生 `switchToAuto` 回调提交结果，保留其清理和 Promise 完成流程。

连续 3 个节点超时后，通过游戏原有托管按钮进入托管。因超时接管的本地角色跳过额外模拟真人思考等待，其他 AI 保持原有节奏。玩家可随时点击原有托管按钮恢复控制；恢复控制或完成一次手动选择后清零连续超时次数。只点击卡牌但没有提交选择不清零。

超时只提交当前决策，不直接跳转阶段、修改目标顺序或执行伤害。卡牌和技能后续时机、濒死救援、死亡和胜负判定继续由原生引擎处理。真人求桃保留自身操作倒计时。

每次操作分别追踪其“确定 / 取消”按钮，超时后统一回收，包括技能回调提前切换事件、延迟重建、失去全局引用的旧容器及技能单独创建的确认按钮。皮肤加载或重写按钮创建方法后继续追踪。排队中的自动选牌回调不再重建已完成的选择界面。下一次选择可正常创建或复用按钮；同一事件继续下一子步骤时重新计时，不会被上一次超时误关闭。出牌时已选中但未提交的牌和目标会先取消选择，再提交超时放弃，避免触发皮肤的“取消后重新选择”。

原生 `PauseManager` 在 `resume()` 后通过微任务解除暂停，不能把暂未解除的 `paused` 标记当成新的选择。超时事件只有在引擎再次实际调用 `pause()` 后才允许重新计时和接管按钮。确认区同时随操作生命周期回收：选将遗留、普通程序提交结束，以及轮到其他角色后延迟重建的按钮都会被移除；仍在等待输入的选将、换牌和技能窗口保持可用。

关闭进度条会同时停用本地超时处理。开局选将和系统动画不计时；联机沿用房间和服务器的原生计时，不叠加本地超时。原生角色或技能显式指定的操作时限优先于扩展的默认时限。

验证覆盖四种样式的实际时限、独立节点、连续超时与取消托管、手动清零、暂停、陈旧回调、联机与选将隔离、自定义 Promise 选择，以及实际原生出牌、响应、求桃、无懈、控制项和强制弃牌步骤。按钮回收回归使用原生 `PauseManager` 的异步恢复流程，并覆盖基础、OL、手杀皮肤与实际 DOM 对局诊断。
