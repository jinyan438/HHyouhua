# 原版摸牌与得牌动画

来源是 `E:/AI/sanguosha/sanguosha2/work/main.js` 的身份局客户端。入口、原文件 SHA-256、类名与默认参数记录在 `assets/card-motion/source.json`。本次动画由代码计算，不需要复制逐帧图片；继续使用 HH 当前的牌面、牌背和边框。

原版 `Rk` 分别从牌堆、弃牌堆、公开牌区、玩家手牌和装备区取得来源坐标，`toHandFunc → lrs.DrawCards` 决定自己入手牌或其他玩家飞牌。HH 对应接入 `$draw`、`$gain`、`$gain2`、`$give`；`$drawAuto`、`$giveAuto` 继续由引擎处理可见性后转入这些入口。开局及手气卡换牌通过 `gameDraw` 中的 `directgain` 接入，普通快照恢复不重播。

| 场景 | 原版逻辑与 HH 对应行为 |
| --- | --- |
| 普通摸牌、技能摸牌、多张摸牌 | `NMt.GetCardsPoint` 从场景中央展开。原版牌面 126×174，间距 26；多张同时移动，按 HH 实际牌宽换算比例。数量型摸牌使用牌背。 |
| 自己获得牌 | `xvi.DrawCard / startHandCardTween` 从来源点直线滑入，300ms、`sineOut`。落点使用 HH 排序、折叠、滚动后的实际手牌位置；可见副本放在场景层，避免被手牌容器裁掉。 |
| 其他玩家获得牌 | `NMt.playNextCardMotion → Zv` 用 700ms 的 `sineOut` 沿二次贝塞尔曲线移动。到达后短暂停留，从第 800ms 开始用 400ms 的 `sineOut` 淡出。目标多牌间距为原版 16。 |
| 从牌堆、弃牌堆或公开牌区获得牌 | `Yki.InitBezierPoint(false)` 的控制点位于目标下方一个原版牌宽；公开得牌优先使用现存牌面副本的实际位置。 |
| 玩家间给牌、拿牌、暗牌转移 | `Yki.getMiddle` 根据移动方向及所在上下半场选择垂直于两端连线的弯曲方向，弯曲距离为两端距离的一半，最少 200 个原版单位。自己接收时沿用原版手牌直线路径。 |

扩展移植的是这些阶段、曲线公式、间距比例和默认缓动时间；Laya 坐标换算为 HH 的场景坐标，并处理 CSS 缩放。Web Animations 对原版正弦进度及二次贝塞尔公式采样，不添加旋转、随机起点或逐张延时。

真实卡牌照常入手牌、排序、选取及结算，不等待视觉副本。自己的得牌只播放一次；连续摸牌改变排序时调整未结束动画的落点。移走、点击新手牌、对局结束及动画异常会清理副本，恢复真实手牌的透明度和过渡样式。看门狗采用原版 `max(700, 400) + 800 + 1000 = 2500ms`；飞牌不会占用弃牌区队列，也不覆盖实体牌已有的 `clone` 指针。

沿用引擎传入的数量或卡牌数组，不额外读取对手隐藏手牌；广播、录像事件与获得牌的日志保留。装备事件优先交给装备动画，避免与这套摸牌动画同时播放。关闭游戏通用动画或使用战棋布局时保留原有处理路径。
