# 逐张分配

离线手动操作时，使用同一组合选择同时选取固定数量的实体牌和等量角色，改为先确认牌池，再逐张指定收牌角色。原来的选牌条件继续生效，例如封赏必须选两张同花色牌。每次从已确认且尚未分配的牌里选一张，再选择一名尚未分配过的角色。

取消当前收牌人会返回剩余牌池，已确认的牌池和先前完成的对应关系保留。全部对应关系完成后，按逐次确认的顺序返回 `links` 和 `targets`；仍由原技能一次性执行 `gaincardMultiple`，中途不移动牌、不触发得失牌效果。选择阶段不提前显示结算目标提示。

适配通过 HH优化的 `cardDistribution.js` 包装 `Player.chooseButtonTarget`，不修改本体或其他扩展文件，也不修改卡牌/目标点击时的全局清理逻辑。当前检查的 75 处组合选择中，符合此类多牌、多角色一一对应写法的是 hh_林 的 `hfengshang` 和本体 OL 董卓的 `olfengshang`，两者共用此流程。数量可变、多牌给一人、拼点选项等其他选择保持原流程；AI 和联机也沿用原流程。

验证覆盖原来的同花色限制、逆序选牌后的对应关系、取消第一/第二次收牌人、重复收牌人排除、原过滤与 AI 回调上下文，以及两个封赏实际技能内容只在全部分配完成后提交一批结果。浏览器使用本体 GameEvent/ContentCompiler、真实卡牌和点击处理、HH优化对话框/控制按钮及自动选择模块，检查手动确认与自动确认两种设置下的完整交互。
