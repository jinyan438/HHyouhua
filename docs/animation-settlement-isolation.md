# 动画与结算检查

结算优化仅处理已接管到达通知的原生移牌及明确关闭动画的数据操作。普通卡牌、技能和未知扩展的默认等待恢复本体处理，多目标间隔、数值等待、自定义动画函数及转场暂停均保留。CSS、Canvas、Spine 和 Web Animations 播放速度、曲线、时长、帧率与资源未作修改。

| 范围 | 检查与保护 |
| --- | --- |
| 摸牌、得牌、给牌及多人分牌 | 自己手牌完整 300ms、其他玩家飞行 700ms 后继续；1200ms 的飞行、停留及淡出总时长保留。用实际浏览器动画时间和到达回调核对。 |
| 装备展示、缩小、装备栏滑入 | 原版 200/267ms 展示、200/267ms 缩小和 300ms 滑入保持顺序；开关两种状态比较完整阶段、变换及清理时间。 |
| 桃、酒、无中、火攻、铁索、闪电、八卦及火雷资源 | 加载并解码真实 Spine 模型，比较开关两种状态的采样时间、各自资源时长及最后一帧前后存活状态。 |
| 普通技能墨迹提示 | CSS 为原资源 1167ms，清理时钟为 1207ms；测试样式及清理计时一致，浏览器核对实际 CSS 动画时长、播放速率和时间进度。 |
| 受伤、治疗、横置翻面、护甲、失去体力 | 默认等待及显式等待均原样委托；不跳过伤害后进入濒死前的停顿，不调整 Spine 或 CSS 时钟。 |
| 判定、改判、拼点、展示牌、死亡及击杀 | 原等待、转场、独立计时器及自定义时长保留；不释放其他模块的暂停。 |
| 卡牌、技能、多目标及未知扩展 | delay / delayx 的无参数、0.5、数值与自定义形式均保留原调用参数和返回值；未知等待不会仅因事件名属于卡牌或技能而删除。 |

自动化检查覆盖上述已知等待入口及异常退出，独立浏览器使用本体事件队列执行得牌、批量分发、技能展示和新旧式 AI 选择。原有卡牌规则、资源校验、装备、技能提示、击杀、判定及界面测试一并运行。此检查涵盖代码路径和计时回归，未逐个运行所有第三方扩展或完整 AI 对局；第三方未知动画等待通过原样委托保留。
