# 结算速度优化

在“HH优化”扩展设置的“游戏速度”下方增加“优化结算速度”，默认开启，切换立即生效并保存。该开关不写入游戏的速度档、HH 速度倍率、动画时长或 AI 思考配置。

原版来源仍是 `E:/AI/sanguosha/sanguosha2/work/main.js`，SHA-256 为 `9da2e7f5f71cd6dbd786d22015f2630661180a22eeb1195da47f26f737b9f078`。`Rk.Handler` 处理移牌消息，`NMt.ShowCardMotion / Zv.StartCardMotionTween` 独立播放视觉动作；`xvi.invalidateLayoutHandCardFlag` 合并同一帧的重复布局，`VUt` 按类型及参数查找特效停顿配置。资源中没有原版服务端的技能结算器，因此本次借鉴客户端的结算与显示分离、布局合并方式，继续使用无名杀原生规则、触发器及事件队列。

主要耗时来自层层叠加的串行停顿，而非改变规则计算所需的时间：`useCard / useSkill` 的默认延迟、多目标之间的半步等待、批量分发的 500/700ms 等待，以及 HH 得牌流程的 `min(400 × HH倍率, 400) + 66ms` 暂停。

开启后：

- 对已识别的卡牌、技能及纯系统结算，跳过无参数的重复展示等待；多目标处理只移除本体 `useCard / useSkill` 两处固定的 `delayx(0.5)` 间隔。
- 得牌仍按原顺序入区、打标记、广播及显示。去掉固定暂停后，等待本次动画实际到达再进入后续移牌：自己手牌 300ms，其他玩家飞牌 700ms，多张并行；700ms 后的停留、淡出继续独立播放。批量分发合并等待本批各接收者到达，原有子事件和触发顺序继续执行。
- HH 出牌、弃牌保留本体 `sync_speed` 转场监听及暂停，等待真实过渡完成；视觉副本、描边、特效和动画时长保持原设置。
- 同一帧、同一上下文重复请求的手牌或弃牌布局各执行一次；其它回调和不同上下文保持顺序。
- 自动结算每经过约 8ms 或 64 次优化等待，会通过本体 `PauseManager` 交还一帧，避免长连锁占满界面线程。即使原调用没有 `await`，本体事件队列也会处理这次让步。

选择、AI 决策等待、无懈询问、求桃、判定及改判、拼点、展示牌、回合阶段、手动暂停、指定数值延迟和自定义动画回调沿用原流程。没有替换 `game.pause / resume`，也不提前释放其它模块持有的暂停。联机及录像沿用原有节奏。

动画展示与重复结算等待分别处理。普通得牌在布局帧前就登记到达通知，等待动画真正开始并到达；自己手牌通过浏览器完成回调交还实体牌，其他玩家按实际动画时间确认 700ms 行程完成，避免后续移牌吞掉尚未开始或正在播放的动画。使用独立时钟，不乘 HH 倍率或修改速度档。手动点击、移走、动画失败、看门狗或对局结束会释放到达通知并清理样式。关闭优化后，新的结算恢复原等待和布局请求，不强行取消正在执行的原有暂停。

验证使用本体 `GameEvent / ContentCompiler / PauseManager` 和 HH 真实得牌流程，以“中”档、`duration = 500ms` 运行同一条确定性结算链：4 次得牌及多目标间隔、一次保留的选择等待和一次显式等待。两条路径的事件顺序、最终 8 张牌、选择等待、动画 1200ms 和所有速度、AI 配置均一致。

| HH 原有倍率 | 关闭优化 | 开启优化 |
| --- | --- | --- |
| ×1 | 约 5.5 秒 | 约 3.5 秒 |
| 用户导出默认值 ×2.5 | 约 10.7 秒 | 约 4.2 秒 |
