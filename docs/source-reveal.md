# 连续亮牌与判定展示

原版来源为 `E:/AI/sanguosha/sanguosha2/work/main.js`。`JiZhan / Wgi` 处理吉占的大小选择及猜测结果，中央牌区 `GMt` 的 `AddCardByCardIds / AddCard` 保留已有牌，`layoutStackCardUis / startEnterFrame` 在新牌加入后重排。文件 SHA-256、方法名和默认参数记录在 `assets/reveal-motion/source.json`。

沿用原版 0.87 牌面比例、5 像素间隔、250ms `Laya.Ease.sineOut`。超出可用宽度时保持一行并重叠排列，横竖屏按实际牌区调整；小高度窗口按可用高度缩放。

`sourceReveal.js` 在原生弹窗打开时接管公开牌的展示节点，放到中央同一排，原来的单次窗口隐藏。吉占一类从牌堆或处理区连续亮牌的流程使用此展示；通用、延时锦囊、装备和技能判定牌共用同一区域，改判时替换对应牌的位置。公开牌保留实际坐标，得牌时可由现有动画从这些位置入手牌。判定状态及生效、失效效果使用 [原版判定动画](source-judge.md)。

不覆写技能、`showCards` 或判定结算。触发时机、原有延迟、记录、知情者、回调、选择和牌的区域变化仍由原生处理。展示只固定牌面副本，不移动实体牌；同次技能结束时通过原生 `insertAfter` 清理，独立判定在该次判定结束后清理，嵌套技能结束后恢复外层牌列，游戏结束时清理副本与监听器。

手牌展示、暗牌、自定义展示窗口、联机、录像和棋盘模式沿用现有展示，避免改变可见性或与其他扩展的自定义交互冲突。

验证包括原版布局方法的 24 组对照，以及真实事件编译器下的原生吉占、洛神技能流程。浏览器检查桌面、横屏、竖屏下的累积展示、得牌结果和结束清理；单元检查补充改判、嵌套技能、重复牌、暗牌和自定义展示保护。判定回调及屯田入田沿用现有回归检查。
