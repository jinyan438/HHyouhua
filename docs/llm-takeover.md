# 大模型接管

打开「扩展 → HH优化 → 大模型接管 → 连接与座位设置」，填写 OpenAI 兼容 API 地址和密钥，点击「拉取模型」后选择模型，也可直接填写模型名称。地址填写到 API 根路径，例如 `https://api.example.com/v1`；粘贴以 `/chat/completions` 或 `/models` 结尾的地址也会自动规范化。保存后开启「接管其他座位」。默认关闭。

DeepSeek 官方接口可填写 `https://api.deepseek.com`，使用该服务的有效 API 密钥。拉取期间按钮显示「正在拉取…」，结果或错误显示在模型区域；成功后使用原生下拉框选择模型，选择「手动填写」可编辑模型名称。安卓按钮直接响应触摸，弹窗内可正常输入和滚动。

诗笺安卓客户端需安装包含 `HHLLMHttp` 原生网络接口的修复版 APK，并更新扩展。旧客户端的网页拦截器缺少认证头的跨域许可，也不能转发模型对话的 POST 请求体；手填模型名称无法解决这个问题。支持该接口时，扩展自动通过原生网络发送模型列表和完整对话，保留认证、超时及取消功能。普通浏览器和没有该接口的客户端继续使用网页请求。原生请求失败不会自动重发对话；HTTP 认证失败显示状态码，域名、证书及连接错误分别提示。

此功能用于离线对局。玩家当前座位保持手动操作，包括玩家自己开启托管时；其他座位的实际选择交给模型。联机与录像沿用原生流程。无可选项、固定结果和锁定效果继续由游戏规则处理；拼点、议事、对策、猜拳、救桃、技能直接用牌及装备栏调整通过原生子选择接入。

接管座位沿用普通 AI 的出牌与结算动画。模型分步选牌、选目标时不显示玩家选择用的灰色蒙版和双剑；从开始请求到提交操作，持续显示原有 AI 思考提示与进度条，并在提示后追加「（LLM）」。多轮请求共用同一段思考显示，长时间等待时进度条循环；失败、取消或对局结束会清理。无懈询问仍同步显示其他 AI 座位，求桃沿用「桃」提示。

「通用提示词」对所有接管座位生效。「座位」下的提示词分别保存，可以逐个切换编辑。每个角色独立保存策略和本局可见牌局档案，其他座位不会接收到其提示词、策略或私下看牌记录。新对局和对局结束会清理上下文。「保留最近策略」限制策略记忆条数，设为 0 时不发送过去的策略。

预设、武将技能文字、牌局摘要、当前场面和选择都在每次请求时临时注入，不保存进座位聊天历史。历史只保留模型通过 `strategy` 主动写下的简短策略，最多 400 字，只记录目标、倾向和后续计划，不自动记录操作、代码或场面。本次选择的工具往返仅临时使用，选择结束即丢弃。固定规则文字放在请求前部，动态场面放在后部，便于服务商前缀缓存；临时注入仍计入当次输入用量。

默认注入本座位及已公开主副将的名称、技能和文字说明。技能代码仅通过 `rules` 按需读取，范围限定在当前可见技能及关联子技能，同份子技能代码不重复嵌入父技能。不发送牌堆内全部卡牌列表、卡牌定义代码或武将传记；只为本座位可见的手牌、场上牌及当前选择涉及的牌提供名称和效果。同名牌的效果集中提供一次，保留花色、点数、属性和转化信息。

完整可见牌局记录保存在本地，每次默认发送最近 16 条精简事件，以及更早事件的计数、伤害/回复/用牌汇总和最多 12 条公开或本座位已知的重要揭示。旧事件的重复场面快照不进入摘要。需要详细信息时，模型可用 `history` 按记录编号、角色或事件类型查询，每页最多 8 条，返回事件发生时保存的完整详情。

对方未公开的手牌、暗将、身份、私有存储、暗置判定牌和未知牌堆顺序不发送。通过原生知情者记录得知的牌可以进入该座位视角。暗牌按钮使用本次选择内的不透明编号，模型可以选择该编号，但无法读取对应暗牌。档案在事件发生时按视角保存，不直接上传全局录像或完整游戏对象，后续公开信息不会倒灌旧记录。

模型通过 `game_action` 使用下列操作。返回纯 JSON 参数的模型也可使用同一接口。

| 操作 | 用途 |
| --- | --- |
| `batch` | 一次提交最多 24 个有序普通操作，例如选牌、选目标、确认；每步原生校验，失败即停，保留已完成步骤。目标也可使用场面中的 `seat:N` |
| `rules` | 使用 `id` 查询当前可见技能及关联子技能的代码 |
| `history` | 使用 `from`、`limit`、`player`、`type` 分页查询本座位完整可见档案 |
| `inspect` | 获取刷新后的当前场面和可选项 |
| `skill` | 发动当前可用的主动技、转化技、重铸等原生技能入口 |
| `card` / `target` / `button` | 选择或取消选择牌、目标、按钮，保留先后顺序 |
| `control` / `bool` / `skill_choice` | 提交选项、是否发动、获得技能等选择 |
| `numbers` | 提交满足原生数值条件的组合 |
| `move` / `swap` | 观星、移牌及普通/分组排序，逐次检查 `filterMove` |
| `tap` | 为演奏提交点击时刻，按原生时间窗口和权重计算结果 |
| `confirm` | 检查条件后交给原生确认与后续结算 |
| `cancel` / `reset` | 放弃响应、结束出牌或退回选择 |

普通选择复用 `game.check`、技能备份/恢复和原生确认接口。转化技能的按钮、目标以及后续子选择继续由游戏生成，不允许模型执行任意 JavaScript、改写角色状态、修改规则或跳过费用。排序与选数检查原生限制；演奏按输入时刻计算得分，模型不能直接指定准确率。

当前选择的 `context` 提供可见的来源技能、归属座位、触发时机、对象和发动/成本/效果阶段，本座位技能优先使用动态文字说明；装备技能也包含在可见规则中。模型据此比较支付成本后的收益。`selection` 按牌、目标和按钮列出最低/最高数量、已选数量、还可选择的数量及剩余容量，随原生动态限制刷新。`canConfirm` 只表示达到最低合法条件，不表示已经选足。

发动技能前需要比较完整结算与不发动的收益，明确后续每一步由谁作选择，按敌方自己的利益评估其选择，计入付出的牌、给对方的资源、伤害回流、有效回复量和限定次数。文字不能明确选择权或与实现有歧义时，用 `rules` 查询实现。主动技能列表和选中技能说明使用本座位当前的动态文字；普通技能仍按需查询代码。

所有可主动决定的技能都使用 `activation` 检查，包括主动技、转化技、非强制的触发询问、直接技选择和成本支付；提交时需要 `reason` 简述成本、后续选择权及相对不发动的净收益。效果明确的普通技能可直接根据文字判断并批量提交。限定技或缺少效果文字时，`requiresRuleReview` 列出必须核查的实现：先查询对应技能代码，等下一次请求收到后再决定，关联备份技能还需核查其限定技来源。批量操作逐步执行此检查，未通过时保留选择，可以继续核查或 `reset` 后改选。其他角色在效果阶段作选择，以及必须完成的结算，不会被当成再次发动技能。此检查只作用于当前选择，代码和理由均不进入策略历史。

仍有容量和可选项时提前 `confirm`，或取消、拒绝非强制的技能相关选择，需要附不超过 160 字的 `reason`，简述少选或放弃的权衡；可在 `batch` 顶层填写，由步骤继承。缺少理由会保留已选内容并反馈给模型继续选择或补充理由，有理由的合法少选和放弃仍可正常提交。此机制适用于所有来源技能和选择类型，不对具体武将或事件设特例。`reason` 仅用于当前选择，不进入座位历史；历史仍只保留 `strategy`。

请求默认 120 秒超时；每次选择最多 96 轮请求，非法操作会反馈给模型修正。连续 3 次请求既未改变选择、也未查到新资料时，停止重复消耗并进入失败处理。失败时默认提示并让原生 AI 完成本次选择，也可设置为「暂停并询问」，选择重试、本次原生 AI 或关闭接管。修改连接设置、关闭接管或结束对局会中止进行中的请求，过期结果不会操作其他事件。设置窗口显示最近一次连接错误和本局请求数、输入/输出 tokens、缓存命中输入 tokens；只累计接口实际返回的用量，缓存命中属于输入的一部分，未返回用量时明确提示。

密钥以密码输入框显示，保存在游戏本地配置中，不写入牌局记录、模型消息或错误提示。浏览器运行时，服务需允许游戏页面进行跨域请求。接口应支持 Chat Completions 的工具调用。摘要和按需查询减少默认输入，仍需为复杂技能查询选择上下文容量足够的模型。

验证：`node --test apps/core/extension/HH优化/tests/llm-*.test.mjs`。测试使用模拟 API，执行本体选择、校验、点击处理及真实事件编译器，覆盖信息隔离、转化技、排序、座位上下文、超时、中止和失败回退，以及安卓原生请求的模型列表、对话参数、取消与错误处理。设置窗口另以原生游戏布局样式验证模型拉取、提示词切换和保存。安卓工程另用本地 HTTP 服务验证真实 Java 请求的认证头、中文 JSON、重定向限制、超时和取消。
