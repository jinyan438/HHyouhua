# HH优化

同一技能的黑色长提示合并到灰色技能标记，直接显示原提示的花色、颜色、文字和换行，红色花色沿用原色；不再同时显示两份标记，详见 [标记说明](docs/source-skill-marks.md)。

手动选择目标时，武将牌下方显示原版字体和描边的“距离N”，超出用牌距离时变红，确认或取消后清除，详见 [距离提示说明](docs/target-distance.md)。

斗地主对局按地主、二号位农民和三号位农民切换座位：自己在右下，地主视角双农民居上，农民视角地主居上、队友分居右侧或左侧，详见 [座位布局说明](docs/doudizhu-layout.md)。

封赏等固定数量的一一对应分牌，现在直接在手牌区显示可分配牌：点一张牌、点一名角色并确认，牌上标出收牌武将，全部确认后统一分牌。原手牌及不符合条件的牌沿用原生暗显；第一张确认后继续按原技能条件限制后续选牌，详见 [逐张分配说明](docs/card-distribution.md)。

无名杀扩展，整合界面美化、游戏优化和身份、斗地主、对决欢乐及国战自由模式全屏选将。默认设置来自用户于 2026-11-14 22:50:31 导出的 HH优化和十周年UI配置。

将本仓库内容放在游戏的 `extension/HH优化/` 目录，在扩展菜单中启用“HH优化”。需要无名杀 1.11.1 或更新版本。

“游戏速度”下方新增默认开启的“优化结算速度”开关，切换立即生效。优化有完整动画到达通知的摸牌、得牌、批量分发及同帧重复布局；卡牌、技能、多目标、伤害回血、横置翻面等展示等待及未知扩展特效沿用原流程，保持原有速度档、HH 倍率和动画时长，详见 [结算优化说明](docs/settlement-optimization.md) 和 [动画检查记录](docs/animation-settlement-isolation.md)。

“启用AI思考延迟”为每次出牌、杀闪、发动技能、弃牌、给牌、移牌和选择选项保留变化的思考停顿；借刀的出杀或交武器、技能直接用牌、按钮回调及唯一操作均在行动前思考，内部子选择共用停顿。普通无牌响应及无闪自动跳过询问保留约 1 秒起的等待，无懈可击沿用原节奏。默认节奏下唯一选项、代选、强制选择及频繁技能保留约 0.9 秒起的等待。支持旧式、已编译和稍后替换的选择内容，思考上下限继续生效，独立于结算优化与游戏速度，详见 [AI思考说明](docs/ai-think-delay.md)。

新增“金色龙纹”背景，首次加载时设为默认背景，可通过对局背景按钮或“选项 → 外观 → 游戏背景”选择。图片随扩展离线提供，之后切换的背景会继续保存。

“全屏选将”用于本地身份、斗地主及对决欢乐模式。对决欢乐模式默认提供12名候选，使用原版六列方形候选、双人大牌预览、金绿选框和选将动画，保留队友代选与替补。新增原版“为他推荐”入口，选择推荐后 AI 队友开局采用该武将。点击查看技能，再次点击候选或上方大牌确认，详见 [选将界面说明](docs/character-selection.md)。

“武将牌样式”提供相邻的“武将宽度”和“武将高度”设置，默认 136×180 像素。宽度可调 80–200，高度可调 120–300，分别修改、保存并立即生效，画像、边框、光效及选将预览同步适配，详见 [尺寸适配说明](docs/player-style-sizing.md)。

对局发光框已换为原版 OL `FX_PaiJu_ZuoWei` 的绿、黄橙、红、蓝四套光效，六种主题沿用原有状态切换。使用原始贴图、遮罩与材质颜色转换，左右边随武将宽度贴合外框，详见 [光框说明](docs/source-player-glow.md)。

受伤特效和伤害数字已替换为原版 OL 动画。普通伤害按 1 点、2–3 点、4 点及以上分档，火、雷、冰使用各自特效；多点伤害支持两位和三位数字，保留原始缩放、残影与淡出时间轴，详见 [伤害动画说明](docs/source-damage-effects.md)。

出牌指示的默认双锤已替换为原版 OL 双剑，保留原始交叉、闪光与 1 秒循环动画。所有指示样式只在黄框选中后显示，蓝框可选角色不显示，取消选中立即清除，详见 [双剑说明](docs/source-target-indicator.md)。

可用及选中的主动技能按钮现使用原版 `fx_UI_AnNIu_ZhuDong` 金色发光与闪烁星点，六种主题共用，不可用时关闭；保留技能文字、标记与点击功能，详见 [按钮光效说明](docs/source-active-skill-glow.md)。

上下移动及排序卡牌的弹窗现使用原版 2025 技能窗口素材，标题与牌区居中，纵向行名、牌面及空槽对齐；“更换光标+loading框”的最后一个样式共用此背景，并随内容扩高，详见 [移牌弹窗说明](docs/source-move-dialog.md)。

武将名现复用原版 `FZLBGBK` 常规字体，势力字居中放大 10%，适用于对局、开局选将和武将详情，详见 [字体说明](docs/source-general-font.md)。

AI 思考进度条统一使用客户端圆头细条、底槽和末端光效，出牌、响应、技能选择、无懈可击及求桃共用这套样式。进度条位于武将牌内部底部、边框上方，随牌宽适配；“出牌 思考中”位于边框下方。满条固定代表 15 秒，按真实经过的时间平滑缩短：实际思考 3 秒只消耗 20%，思考结束后移除剩余进度条。“出牌 思考中”复用原出牌提示样式，仅在实际 AI 思考等待期间显示；交互结算期间不显示，也不添加替代提示。连续选择各自计时，快速操作只显示进度条，仍遵守原有思考时长及提示开关。

无懈可击询问及相关技能子选择期间，所有其他 AI 同步显示思考进度与提示，共用起始时间并一起结束。玩家没有无懈可击或转换技能时，也不会因只有响应者显示思考而暴露其手牌；显示不依赖各角色的响应能力。

玩家进度条开启后，每个本地手动操作独立计时，默认 15 秒。超时优先取消或不响应，强制选择由原生默认逻辑完成；连续 3 次超时进入托管，完成手动选择或取消托管后清零。暂停时停止计时，联机沿用房间规则；“操作时限”替换原来的进度条速度设置，详见 [玩家超时说明](docs/player-action-timer.md)。

“部件管理 → 进度条”新增“OL客户端进度条”，使用 OL 客户端 `gameBase` 图集中的方头黄色主进度条、底槽与末端光效，按原版 748×15 布局显示，宽度随窗口适配，沿用操作时限及进度条高度设置。当前出牌、响应、无懈可击等操作提示居中显示在进度条上，文字底部与条底对齐，并随操作内容及进度条高度同步更新。

“装备牌移动优化”开启后，装备牌使用原版身份局的完整入栏逻辑：在武将牌左上侧抬升放大、缩至入栏点，移动结束后装备条再从左向右滑入。复用原版默认阶段时间、缓动与缩小比例，普通玩家抬升及缩小各 200ms，本地玩家各 267ms，装备条滑入 300ms，坐标随实际武将牌和装备栏适配。普通使用、技能直接置入（含 `hh_sp3` 吕玲绮“妆戎”）、装备转移及虚拟装备共用；装备被取消、替换或移走时清理副本和等待，拆除及弃置装备仍沿用普通弃牌动画。

装备栏现复用原版 OL 的黑色半透明底图、武器/防具/坐骑/宝物图标、描边花色与点数，装备名和范围使用原版 `FZLBGBK` 常规字体。武将牌内按原版固定四行，空位保留；双马与宝物位被装备、废除或技能占用时，双马并列第三行并省略名称，宝物占第四行。单张进攻坐骑优先使用空闲防御坐骑位，恢复或腾空装备位时自动回排。六种主题共用，独立装备面板保留完整名称及原有槽位；虚拟装备、装备技能及废除栏保留原有功能。资源与布局来源见 [装备栏说明](docs/source-equipment.md)。

移动优化关闭时，装备条直接滑入。文字更新、已有装备和栏内排序不重播动画。

摸牌和得牌现使用原版身份局的轨迹：自己从来源位置用 300ms 正弦缓动滑入实际手牌位置，其他玩家按 700ms 贝塞尔曲线飞牌，再按原版时序淡出。混合渠道按持有者、来源区域和技能牌堆分别展开，保留各批触发时序；新批手牌按原版重新启动缓动。覆盖普通／技能摸牌、多张摸牌、公开得牌、玩家间给牌与暗牌转移、批量分发、开局及手气卡换牌；保留当前牌面、牌背及可见性规则。详见 [摸牌动画来源](docs/source-draw-motion.md)。

在游戏的“扩展 → HH优化”中点击“检查扩展更新”，确认后会从本仓库的默认分支下载更新。更新按远程提交识别，支持同版本号下的代码修复。只下载发生变化的文件，校验通过后才安装；安装失败会恢复旧文件，意外中断后会在下次启动恢复。完成后点击“重启游戏”生效。需要联网及游戏文件读写权限。

更新临时文件、恢复备份放在 `.hh-update/`，已安装提交信息放在 `.hh-update-state.json`，均已加入 Git 忽略。更新器不会修改游戏保存的个人设置。

2.0.2 修复安卓更新器的文件写入、截断及错误回调兼容问题。下载暂存、备份、安装和恢复都会读回校验；启动恢复失败时只暂停 HH优化的加载，保留修复入口。

手机已出现更新失败、重启无法进入游戏时，请先恢复到能启动的版本，移除旧 HH优化后导入 2.0.2 完整包，再重启。旧更新器本身有此兼容问题，本次请使用离线完整包安装。

提交扩展修改前可运行：

```sh
node tools/build-update-manifest.mjs
node --test tests/*.test.mjs
git add .
git commit -m "描述本次修改"
git push
```

`update-manifest.json` 用于新安装时识别本地文件。之后的更新直接比较 GitHub 文件清单，不要求每次远程提交都重新生成清单。
